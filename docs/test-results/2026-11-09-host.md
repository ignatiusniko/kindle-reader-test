## Finding: musl allocator fragmentation (MEM-01)

Same MEM-01 loop (8-page 1000×1500 JPEG book, page buffers dropped every
turn, budget back to 0 each turn), RSS sampled 10× per run:

| Build | 500 turns | 4,000 turns |
|---|---|---|
| x86_64 glibc | ~10–12 MiB, flat | 9.3 → 10.4 MiB, flat |
| x86_64 musl (default allocator) | 9.9 → 19.0 MiB | 18.1 → **80.4 MiB**, still rising |
| x86_64 musl + mimalloc | — | 21.7 → 18.1 … 21.2 MiB, flat |

Conclusion: not a logical leak (reservations return to zero every turn);
the musl allocator fragments under this allocation pattern. The Kindle build
is musl, so this would have become an OOM over a long reading session.
Fix: mimalloc as global allocator on musl targets (`decisions/0003`).
Must be re-measured on the device in G6 (MEM-01).
